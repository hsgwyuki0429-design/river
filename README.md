# River — 水と砂による河川地形シミュレーションゲーム

砂の高低差をつくり、水源の流量を調整すると、川・谷・池・中州・扇状地が
「勝手に」できていくブラウザゲームです。iPhone の縦画面を第一基準にしています。

水が地形を変え、変わった地形が次の水流を変える **双方向のシミュレーション** が中心です。

```
水が地形に沿って流れる
   ↓
強い流れが砂を侵食する（掃流力が限界値を超えたとき）
   ↓
削られた砂を水が運搬する（水の移動量に比例して移流）
   ↓
流れが弱くなると砂が堆積する（運搬能力を超えた分）
   ↓
堆積・侵食で bedHeight が変化する
   ↓
変化後の地形で水面高が変わり、次の流量が変わる ──┘
```

## 遊び方

| 操作 | 内容 |
| --- | --- |
| 指1本でなぞる | 砂を盛る／削る。同じ場所を長く押すほど変化量が増える |
| 指2本 | 視点の移動と拡大縮小（地形編集とは誤認されない） |
| 右端の縦スライダー | 水源流量。蛇行観察では有限タンクの循環ポンプ流量 |
| 下部ツールバー | 盛る・削る・視点移動・視点切替・ブラシの大きさ・速度 |
| ☰ メニュー | 初期化・保存・読み込み・水源移動・デバッグ表示・地形変化倍率・解像度 |

プレイヤーが直接操作するのは「砂の高低差」と「水源の水量」の2つだけです。
川を直接描いたり、水を好きな位置に置いたりはできません。

タイトルの「蛇行観察」は、通常より縦に長い侵食可能な氾濫原です。初期水路にあるのは
再現可能なごく小さい非対称だけで、蛇行・河道切断・三日月湖は水と土砂の相互作用から
生じます。専用ボタンで地形を書き換える演出はありません。

## シミュレーションの方式

### 水流：virtual-pipe 法 ＋ Manning 摩擦

隣接8セル間に「仮想パイプ」を置き、**水面高** `waterSurface = bedHeight + waterDepth`
の差で流量を加速し、摩擦で減衰させます。地盤高だけを見た「最も低い隣へ移す」方式では
ありません。

```
hFlow = waterSurface_i - max(bedHeight_i, bedHeight_j)   有効水深（堤より低ければ 0）
f    += dt * (fluxGain * cellSize * hFlow) * g * (surf_i - surf_j) / pipeLength
f     = f / (1 + dt * g * n^2 * v / hFlow^(4/3))          Manning 摩擦（半陰的）
f     = min(f, froudeMax * sqrt(g*hFlow) * hFlow * cellSize)   フルード数の上限
f    *= min(1, セル内の水量 / 総流出量)                    保有水量を超えて出さない
```

- 摩擦を半陰的に解いているので、終端流速は Manning 則 `v = d^(2/3)·√S / n` になります。
  水深が深いほど・勾配が急なほど速く流れ、永久振動は摩擦で減衰します。
- `hFlow` に上流側の水面を使う（hydrostatic reconstruction）ことで、乾いたセルへの
  流入も、堤を越えない挙動も、境界での破綻なしに扱えます。
- 流量は保有水量でスケーリングされるため、**水深が負になることはありません**。
- 斜めパイプは長さ `cellSize·√2`、接続幅重み `1/√2` とし、全8方向の流出量を一括で
  保有水量以下へ縮小します。同じ8方向流束を浮遊砂の移流と流速ベクトルにも使います。
- 既存お題は攻略性と低負荷を維持する4方向設定、自由モードと蛇行観察は8方向設定です。
  方式は `diagonalFlowEnabled` で明示され、8方向の開境界・閉境界・循環境界をテストしています。
- 時間刻みは固定（既定 1/60 秒）。各ステップの内部で CFL 条件と陽解法の安定条件から
  サブステップ数を決めます。フレームレートが揺れても結果は変わりません。

### 侵食・運搬・堆積

見た目の演出ではなく、実際に `bedHeight` を増減させています。

```
slope    = |∇(bedHeight + waterDepth)|            水面勾配（中央差分・上限あり）
shear    = ρ · g · waterDepth · slope             掃流力 [Pa]
capacity = capacityRate · d · speed^1.3 · (slope+ε)^0.5     運搬能力（濃度上限つき）

浮遊土砂 < 運搬能力のとき（侵食）
  erosion = erosionRate · max(0, shear - criticalShear) · erodibility · morph · dt
  上限: 運搬能力の不足分 / 1秒あたりの侵食量上限 / 岩盤までの残り厚み
  bedHeight -= erosion ; suspendedSediment += erosion

浮遊土砂 > 運搬能力のとき（堆積）
  deposition = depositionRate · (suspendedSediment - capacity) · morph · dt
  bedHeight += deposition ; suspendedSediment -= deposition
```

浮遊土砂の移動は、水流の計算に使ったのと **同じ流量** で行います。
セルから出て行く水の体積比だけ土砂も出て行くので、砂が水と無関係に瞬間移動することは
ありません。流速が落ちた場所・勾配が緩んだ場所・川幅が広がった場所・池に入った場所で
運搬能力が下がり、そこに砂が積もります。

`morphologicalTimeScale`（既定 8）は水の移動速度と地形変化速度を分離する係数です。
毎フレーム地形を大きく削るのではなく、物理モデルで計算した変化量にこの倍率を掛けます。
メニューから 0.25〜4 倍に変更できます。

### 安息角による崩落

水流とは別に、隣接セルとの高さ差が安息角 `tanθ · cellSize` を超えたら高い方から低い方へ
砂を移します。乾いた砂 (tanθ=0.7) より水を含んだ砂 (tanθ=0.42) の方が崩れやすくなります。
一度に崩すのは「最大超過分の半分」までに制限しているので、複数ステップで自然に落ち着きます。
川岸が下部から侵食されると、上部が安息角を超えて崩れてきます。

### 上下循環

蛇行観察では上下端を直接隣接させません。下端流出を盤面外の有限タンクへ回収し、次の
サブステップ以降に上端2行へ滑らかに再投入します。タンクは水、浮遊砂、掃流砂、下端の
横方向流出分布、累積循環量を保持します。放出時は必ず

```
releasedSediment = tankSediment * (releasedWater / tankWaterBeforeRelease)
```

とし、水と砂の濃度を保ちます。スライダーは新しい水を生成せず、タンクに存在する量までを
送り出すポンプです。地盤は循環せず、下端を通った移動中土砂だけが戻ります。

### 曲率・二次流・河岸移動

流速ベクトルを3×3近傍で平滑化・正規化し、流線方向の接線変化から符号付き曲率を求めます。
低流速・乾燥セルは曲率0、曲率は上限つきです。二次流は曲率へ時定数つきで追従し、上流値も
混ぜるため、曲がり頂点より少し下流まで残ります。

- 曲率の外側にある、水際より高い河岸根元へ侵食を追加します。掃流力超過、水深、速度、
  曲率、`erodibility` を掛け、`bedrockHeight` で止めます。
- 内岸の低速域では運搬能力低下に加えて点砂州堆積を促進します。
- 限界掃流力を超えた砂の一部を `bedloadSediment` とし、主流方向、下り河床勾配、二次流の
  内岸向き成分を合成して8近傍へ保存的に移動します。
- 河岸侵食、掃流砂、安息角崩落はすべて差分バッファを使い、走査中に隣接地形を直接変更しません。

このフィードバックで外岸侵食と内岸堆積が曲がりを増幅し、首が薄くなると増水時の越流侵食が
短い流路を育てます。短路の抵抗が下がると流量が自然に移り、旧流路は低速化して入口に堆積します。
三日月湖検出は、主流と非連結・最低面積・低流速継続時間・細長さだけを読み、地形や水を変更しません。

### 水量・土砂量の保存

各パスは加算と減算が対になっていて、保存則を壊しません。

- **水**: 流入・流出は同じ流量値から計算するので、内部のやり取りは厳密に相殺されます。
  盤面外・排水口へ出た分は `budget.waterOut`、水源から加えた分は `budget.waterAdded` に記録。
  `盤面内の水 = 初期 + 追加 - 流出 - 蒸発` を毎フレーム検算します。
- **土砂**: 侵食は `bedHeight` を減らした分だけ `suspendedSediment` または
  `bedloadSediment` を増やし、堆積は逆。
  移流は水と同じ流量比で行い、崩落は差分バッファの総和が 0 になるように配ります。
  `地盤 + 浮遊 + 掃流 + 循環中土砂 = 初期 + 盛った量 - 削った量 - 盤面外流出` を検算します。

循環モードの水は `盤面内水 + 循環中水 = 初期総水量 - 蒸発` で検算し、内部循環を
`waterAdded` / `waterOut` に二重計上しません。

誤差はメニューの「収支・負荷パネル」で常時確認でき、許容値
（`Simulation.budgetWithinTolerance()`、相対 1e-4）を超えるとテストが落ちます。
実測では float32 の丸め由来の相対 1e-6 程度に収まっています。

## ステージ

成功条件・失敗条件・使用可能な砂量・目標時間・評価項目はすべて
`src/game/stages.ts` のデータで、判定器 (`objectives.ts`) は条件データだけを見ます。

| # | ステージ | 成功条件 | 失敗条件 | 砂 |
| --- | --- | --- | --- | --- |
| 1 | 水をゴールへ届ける | ゴールの池を水深 12cm 以上で 50% 覆う | 時間切れ (280秒) | 65 m³ |
| 2 | 2つの水域をつなぐ | 上下の池が水路でつながる | 時間切れ (330秒) | 80 m³ |
| 3 | 集落を浸水させずに排水する | 出口から 90 m³ 排水 | 集落の浸水 2.0 m³ 超 / 時間切れ | 68 m³ |
| 4 | 限られた砂で洪水を防ぐ | 出口から 140 m³ 流しきる | 低地の浸水 2.0 m³ 超 / 時間切れ | 30 m³ |
| 5 | 指定区域に土砂を堆積させる | 指定区域に 32 m³ 堆積 | 土砂の盤面外流出 25 m³ 超 / 時間切れ | 無制限 |

評価は「目標達成度／浸水禁止区域への流入量／使用した砂の量／流失した水量／
制限時間／指定区域への堆積量」を集計し、星3段階で表示します。

`test/stages.test.ts` は各ステージを想定解でヘッドレスに攻略し、
クリアできること・放置すると失敗することを検証しています。

## 端末性能への対応

- 起動時に `hardwareConcurrency` と `deviceMemory` から格子解像度を選びます
  （低 64×96 / 中 80×120 / 高 96×144、セル 0.5 m）。メニューから手動変更もできます。
- 実行中に平均フレーム時間を見て、重いときは
  **描画の間引き → 描画拡大率 → サブステップ数 → 描画解像度** の順に段階的に下げます。
  計算が壊れる方向には落としません。
- 描画とシミュレーションは別々の頻度で更新できます。
- 蛇行観察は低品質で 64×192 セル（初期川幅約8セル、縦長さは川幅の20倍以上）。重い曲率・
  河岸・掃流砂パスはこのプリセットだけで有効にし、既存お題の実測負荷を維持します。

## 主な調整パラメータ

| パラメータ | 既定 | 推奨範囲 | 意味 |
| --- | ---: | ---: | --- |
| `bankErosionRate` | `8e-6` | `4e-6`〜`3e-5` | 外岸の削れやすさ |
| `curvatureErosionGain` | `2.2` | `1`〜`4` | 曲率による外岸侵食増幅 |
| `secondaryFlowStrength` | `0.75` | `0.4`〜`1.2` | 曲率から二次流への結合 |
| `secondaryFlowRelaxation` | `1.8 s` | `0.8`〜`4 s` | 二次流の遅れ・残り方 |
| `pointBarDepositionGain` | `0.55` | `0.3`〜`1.2` | 内岸砂州の堆積増幅 |
| `bedloadRate` | `2.5e-6` | `1e-6`〜`8e-6` | 掃流砂への取り込み |
| `bedloadTransportRate` | `1.4 s⁻¹` | `0.6`〜`2.5` | 掃流砂の移動割合 |
| `curvatureMax` | `0.8 m⁻¹` | `0.3`〜`1.2` | 1セルノイズの上限 |

保存形式は v2 です。循環タンク、掃流砂、二次流、低流速継続時間、全物理パラメータ、プリセット、
乱数シードを保存します。v1データも読み込め、存在しない状態には安全な既定値を使います。

## 今後の拡張

MVP では砂は1種類ですが、データ構造は拡張を見込んでいます。

- **砂の種類**（粗い砂・細かい砂・砂利・粘土）: `erodibility` と同じ形の per-cell 配列を
  種類ごとに持ち、`capacityRate` / `criticalShear` を種類別にします。
- **岩盤**: `bedrockHeight`（掘削・侵食の下限）と `erodibility = 0` で既に表現できます。
- **植生**: `erodibility` を下げる per-cell 係数として追加します。
- **雨**: `addSourceWater` と同じ形の、盤面全体への一様な流入項を足します。
- **蒸発**: `SimParams.evaporation` が実装済み（既定 0）。
- **地下への浸透**: 蒸発と同じ形の吸い込み項として追加します。
